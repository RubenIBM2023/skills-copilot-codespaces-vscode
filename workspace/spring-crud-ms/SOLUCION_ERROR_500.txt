🔍 SOLUCIÓN DE PROBLEMAS
█████████████████████████████████████████████████████████████████████████████████

PROBLEMA 1: "Error 404: Not Found"
──────────────────────────────────────────────────────────────────────────────
✅ SOLUCIÓN:
   └─ Verifica que la ruta sea correcta:
      • /api/v1/products (para ProductController)
      • /orders (para OrderController)
      • /shipments (para ShipmentController)
      • /invoices (para InvoiceController)
   └─ Abre F12 en navegador → Network → ve qué ruta se envía
   └─ Copia y prueba en curl

PROBLEMA 2: "Error 500: Internal Server Error"
──────────────────────────────────────────────────────────────────────────────
✅ CAUSAS POSIBLES:
   1. Base de datos no inicializada
   2. Validación fallida (campos requeridos faltando)
   3. MongoDB no disponible

✅ SOLUCIÓN:
   └─ Abre F12 → Console → ve el error exacto
   └─ Revisa los logs de la aplicación en PowerShell
   └─ Busca "ERROR" o "Exception" en los logs
   └─ Verifica que todos los campos requeridos se envíen:
      • name (requerido, no vacío)
      • price (requerido, > 0)
      • stock (requerido, >= 0)
      • category (requerido, no vacío)

PROBLEMA 3: "CORS Error"
──────────────────────────────────────────────────────────────────────────────
✅ SOLUCIÓN:
   └─ Ya está configurado @CrossOrigin en todos los controladores
   └─ Si persiste, intenta desde la consola del navegador:
      fetch('http://localhost:8080/api/v1/products?size=10')
        .then(r => r.json())
        .then(d => console.log(d))

PROBLEMA 4: "MongoDB Connection Refused"
──────────────────────────────────────────────────────────────────────────────
✅ CAUSA:
   └─ MongoDB embebido (Flapdoodle) debe inicializarse
   └─ Primera ejecución tarda más

✅ SOLUCIÓN:
   └─ Espera 30-60 segundos después de iniciar
   └─ Revisa logs para "Embedded MongoDB Server started"
   └─ Si persiste, revisa puerto 27017:
      netstat -ano | findstr :27017

PROBLEMA 5: "Puerto 8080 en uso"
──────────────────────────────────────────────────────────────────────────────
✅ SOLUCIÓN:
   └─ Mata el proceso anterior:
      netstat -ano | findstr :8080
      taskkill /PID <PID> /F
   
   └─ O cambia el puerto en application.properties:
      server.port=8081
   
   └─ Luego accede desde: http://localhost:8081/orders.html
